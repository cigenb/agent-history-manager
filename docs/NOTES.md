# 删除与残留清理审计

## 修复范围

| 来源 | 问题与处理 |
| --- | --- |
| Claude Code | 残留判断先收集所有项目目录中的会话 ID；保留其他目录中的有效副本仍在使用的附件和文件历史。 |
| Claude Code | 残留检查直接核对提问和回答，保留索引未及时收录、JSON 带空格、记录不完整或无法读取的会话。 |
| Claude Code | 项目删除保留其他项目共用的记忆目录；残留检查保留仍被项目使用的记忆。活进程的状态文件无法读取时停止删除。 |
| Claude Code | 没有正式提问、但有命令或文字回答的记录列入「只看临时和脚本会话」，可查看、搜索和删除；标题可使用首条命令或回答。 |
| Claude Code 记忆 | 索引只匹配本地文件，忽略已有删除标记和代码示例；删除时保留同一行中的其他链接，不改写存在歧义的同名 wiki 引用。 |
| Claude Code 记忆 | 读取引用失败时不删除原记忆；备份目录不会因时间戳相同而覆盖；还原前检查全部备份文件，拒绝越界路径、符号链接和目录联接。 |
| Grok | 修正残留入口的分派；残留移到回收站，普通会话继续使用官方 CLI 删除。 |
| Grok | 按元数据中的实际 ID 关联子代理，只递归隐藏子会话，阻止路径穿越和循环引用。普通删除与残留清理均保护运行中的后代。 |
| Grok | 父残留及其多层子会话一次列入计划；用户提问、回答、无法读取和不完整的日志均不作为空会话删除。 |
| Grok | 只有文字回答而没有提问的顶层记录归入「只看临时和脚本会话」，标题可取首条回答；重建旧缓存后即可管理，追加提问后恢复普通分类。 |
| Grok | 删除每个会话及回收子代理目录前复查运行状态，保护删除过程中重新打开的会话；状态文件结构损坏时停止删除。 |
| Codex | 初始化、写管道或线程删除失败时，不继续清理缓存、生成图片和输出目录。 |
| Codex | 名称索引和提问历史按记录中的线程 ID 清理，保留标题或正文中提到该 ID 的其他记录；残留证据也检查状态备份和提问历史。 |
| Codex | 保留远程线程缓存、注册项目目录及其他线程使用的目录；归属比较统一 Windows 路径写法，只从有效的日期目录和 `outputs` 路径推导工作区根。 |
| Codex | 同一 ID 的 rollout 只调用一次删除，并回收官方删除后剩下的副本；任何副本近期改动、或第二个 ID 仍有索引时，整组保留。 |
| Codex | 工作目录根必须为绝对路径，读取线程占用失败时保留目录；两个文件名 ID 均被选中时回收剩余副本，官方删除后再次检查 Desktop 是否打开再清缓存。 |
| 共用 | 删除计划按路径去重；大小统计和附件删除不跟随 junction 到其他目录。 |

## 验证

- `pnpm test`：77 条测试通过，其中 59 条覆盖删除、残留清理、记忆及无提问记录的管理入口。
- `pnpm typecheck`：主进程和界面类型检查通过。
- 测试使用独立临时目录、真实 SQLite 文件和模拟 CLI、回收站；覆盖分类保留、跨目录副本、多层子代理、运行中保护、损坏数据、部分失败、缓存备份和 junction。
- 记忆专项覆盖直接链接、相对链接、锚点、wiki 别名、同名冲突、代码示例、中英文删除标记、备份原样还原、覆盖确认、缺失备份文件和路径越界。
- Codex 无提问、无标题、无消息的已索引主线程仍有列表和删除入口；只有回答的线程可以查看和搜索。
- 本机官方 Codex app-server 在隔离的 `CODEX_HOME` 中通过 `initialize`、`thread/start`、`thread/delete` 协议检查，未发送模型请求。
- `pnpm dist:dir`：构建本地免安装版。

## 保留边界

近期改动的残留、运行中的会话、无法确认归属的数据和损坏的记录不作空会话清理。Claude 残留中的孤立项目记忆默认不勾选；用户取消的类别继续保留。记忆删除备份和 Codex 缓存备份保存在程序自己的数据目录中。

Codex 数据库保持只读；没有 rollout、无法交给 `thread/delete` 的孤立日志行不直接清理。Grok 普通会话的永久删除仍由官方 CLI 执行。
